# NetOps 分布式部署架构文档

## 1. 架构概述

NetOps 网络运维监控平台采用 **级联式分布式架构**，支持总部（L0）→ 省级（L1）→ 地市级（L2）多级部署，本地采集、上级汇总。

```
┌─────────────────────────────────────────┐
│  L0 总部中心（总库 + MQTT Broker）       │
│  - 汇总所有下级节点数据                   │
│  - 全局拓扑 / 告警 / 报表                 │
└──────────────┬──────────────────────────┘
               │ MQTT 上报 / REST 拉取
   ┌───────────┼───────────┐
   ▼                       ▼
┌────────┐            ┌────────┐
│ L1 省A │            │ L1 省B │
└───┬────┘            └───┬────┘
    │                     │
  ┌─┴─┐                 ┌─┴─┐
  ▼   ▼                 ▼   ▼
 L2  L2               L2  L2
```

## 2. 节点模型

| 字段 | 说明 |
|---|---|
| node_id | 节点唯一标识（UUID） |
| name | 节点名称（如"新疆电力"） |
| level | 层级：L0/L1/L2 |
| parent_id | 上级节点 ID |
| addr | 节点地址（域名或 IPv4） |
| token | 节点独立接入密钥 |
| online | 在线状态 |
| last_seen | 最后心跳时间 |

## 3. 部署模式

初始化时或系统设置中可切换：

- **单机模式（standalone）**：所有数据存本地 SQLite/MySQL，无上报
- **分布式模式（distributed）**：本地采集后通过 MQTT 上报上级，同时接收下级上报

切换后需重启系统生效。

## 4. 数据流向

1. **采集层**：各节点通过 SNMP/ICMP/SSH 采集本机设备、容器、数据库指标
2. **本地存储**：指标写入本地时序库（内置/TDengine）
3. **上报层**：本地数据按 node_id 标记后，通过 MQTT 主题上报上级
4. **汇总层**：上级节点订阅下级主题，写入总库
5. **查询层**：总部用户可查全部；分部用户仅查本节点及下级（NodeScope 权限隔离）

## 5. 节点分组

- 支持预建分组（如"华北分部""华南分部"）
- 下级节点可手动或自动归入分组
- 总部视图按分组聚合统计

## 6. 认证与安全

- 上下级通信使用 **节点独立 token**（非全局共享）
- MQTT 支持 TLS
- JWT Claims 携带 NodeScope，查询自动过滤
- 敏感操作（删除/回滚/重置密码）二次确认 + 审计日志

## 7. 数据库支持

- 业务库：SQLite / MySQL / PostgreSQL / OceanBase / Oracle / 达梦 DM / 人大金仓 KingbaseES
- 时序库：内置内存 / TDengine / InfluxDB
- 所有数据库类型在"数据库迁移"页面切换，保存后自动重启

### 异构数据库上报

各下级节点**本地业务库可以任意选型**（总部用 MySQL，分部用 Kingbase，基层用 SQLite），互不影响：

1. 采集层统一把指标写入本地**时序库**（各节点可不同）
2. 上报时由节点**统一序列化为 JSON**（含 node_id、时间戳、指标名、值）
3. 通过 MQTT 主题 `netops/{node_id}/metrics` 推送到上级 MQTT Broker
4. 上级节点订阅后，**写入自己的总库**（上级用什么库就写什么库，与下级无关）
5. 业务数据（配置备份、告警事件、资源资产）走同样流程：本地库存储 → JSON 序列化 → MQTT 上报 → 上级入库

即：**数据库差异被 GORM 方言层屏蔽，跨节点只走 JSON over MQTT**，因此总部与各分部数据库类型可完全异构。

| 层 | 数据库 | 说明 |
|---|---|---|
| 下级本地 | 任意（SQLite/MySQL/Kingbase/DM/OceanBase...） | 本机采集存储，可国产化 |
| 传输 | MQTT JSON | 与数据库无关 |
| 上级总库 | 任意 | 汇总写入，与下级无关 |

## 9. 部署方式

- **Windows**：解压 zip → 运行 start.bat
- **Linux**：解压 tar.gz → chmod +x install.sh → ./install.sh install

### Windows 安装 MQTT Broker（EMQX）

分布式模式需要 MQTT Broker（默认 1883 端口）：

1. 下载 EMQX Windows 版：https://www.emqx.com/zh/downloads/broker
2. 解压 `emqx-x.x.x-windows-amd64.zip`
3. 管理员权限打开 CMD，进入解压目录 `bin\`
4. 安装并启动服务：
   ```
   emqx install
   emqx start
   ```
5. 访问 http://127.0.0.1:18083 （默认账号 admin / public）
6. 在 EMQX → 访问控制 → 认证 → 添加用户名密码（如 netops / 自定义密码）
7. NetOps 初始化时 MQTT 地址填 `127.0.0.1:1883`，填上述账号密码

> 单机模式不需要 MQTT。

### Linux 安装 MQTT Broker（EMQX / Mosquitto）

**方式一：EMQX（推荐）**

```bash
# Ubuntu/Debian
wget https://www.emqx.com/en/downloads/broker/5.8.6/emqx-5.8.6-ubuntu22.04-amd64.deb
sudo dpkg -i emqx-5.8.6-ubuntu22.04-amd64.deb
sudo systemctl enable --now emqx

# 控制台 http://服务器IP:18083  admin/public
# 添加认证用户：emqx ctl admins add netops '自定义密码'
```

**方式二：Mosquitto（轻量）**

```bash
sudo apt update
sudo apt install -y mosquitto mosquitto-clients

# 设置密码
sudo mosquitto_passwd -c /etc/mosquitto/passwd netops
# 输入密码

# 配置 /etc/mosquitto/mosquitto.conf，末尾加：
listener 1883
allow_anonymous false
password_file /etc/mosquitto/passwd

sudo systemctl restart mosquitto
sudo systemctl enable mosquitto
```

NetOps 初始化时 MQTT 地址填 `服务器IP:1883`，填上述账号密码。
